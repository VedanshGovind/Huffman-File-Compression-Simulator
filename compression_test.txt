HUFFMAN COMPRESSION TEST FILE
=============================
Purpose:  a round-trip test document for the Huffman Compression Simulator.
Method:   1) Compress this file.   2) Decompress the .hcm.   3) Compare —
          the recovered text must match this file EXACTLY, character for
          character, including every space, newline and symbol.


SECTION 1 — PROSE (real English, natural letter frequencies)
------------------------------------------------------------
Data compression has been part of computing since the earliest days of
electronic machines. Before Huffman, most systems stored text in fixed
width: every character took exactly eight bits, whether it was a common
letter like e or a rare one like q. That wastes an enormous amount of
space, because English is not evenly distributed. The letter e appears
roughly thirteen percent of the time, while z appears far less often.

Huffman coding exploits exactly this unevenness. It builds a tree from the
actual frequencies of the file being compressed, so the code is tuned to
this document in particular. That is why the code table shown by the
simulator will look different if you compress a different file: the same
letter can be one or two bits here and three or four bits somewhere else.

Lossless compression is a promise: nothing may be lost on the way in and
out. A single dropped bit in the middle of a file can shift every symbol
that follows, which is why the decoder walks the stored tree one bit at a
time instead of chopping the stream into fixed-size pieces. If the tree in
the header and the bitstream payload ever disagree, the decoder will tell
you the file is corrupt instead of silently producing garbage.
